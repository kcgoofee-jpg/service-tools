## 二、 数据潜能与分析盲区（能挖而未挖出的信息）

### 1. 现有数据中可深挖但原系统遗漏的情报
1. **请求时间间隔（Inter-Arrival Time, IAT）与时序抖动**：
   - 提取请求时间差 $\Delta t$，可发现高度机械化的固定周期（如 15.0 秒定时循环），直接锁定无人值守脚本。
2. **多 Key 跨账号协同挖掘（一人多号 / Sybil 多开）—— 原系统最大防作弊盲区**：
   - 原 `share_guard` 只关注“单 Key 多人借用”，**完全未建立“单人/单设备多 Key 刷额度”模型**；
   - 交叉对比 `(net, client_sig, user_agent)` 可以在几秒内识别出同一用户注册多个 Discord 小号领 Key 的行为。
3. **客户端软件生态画像**：
   - 结合 UA、请求路径调用链（如在生图前高频调用 tags），能精准还原客户端软件：
     - `axios/1.18.0`：自写脚本或未包装的 Web 前端；
     - `NAI-Launcher/1.0.0`：第三方桌面启动器；
     - `TauriTavern/2.1.0`：SillyTavern（酒馆）客户端；
     - `App/278 CFNetwork/...`：iOS 原生画图 App。
4. **上游服务异常聚类**：
   - 识别出 10-10 22:14~22:26 期间 NovelAI 官方图片后端发生的大面积宕机（连续 500 且耗时 ~30s 超时）。
   - 识别出由于客户端参数异常导致的 8 次上游 GPU 精度溢出（`NaN detected in generation output`）。

### 2. 网关可采集但尚未采集的硬核指纹
1. **TLS / HTTP2 客户端指纹（JA3 / JA4）**：
   - 伪造 UA 成本极低，但 TLS 握手 Client Hello 的密码套件与扩展顺序几乎无法被简易脚本伪造。
2. **HTTP 标头集（Header Signature）**：
   - 标头大小写顺序、`Accept-Language`、`Sec-Ch-Ua` 完整集。

## 五、 防护模块改造与工程落地设计

基于审计发现的结构性缺陷，进行以下代码与模块落地：

1. **重构增强小号识别模块（`app/alt_guard.py`）**：
   - 修复原代码中 `zip(rows, rows[1:])` 依赖全局相邻请求导致的交替漏判缺陷，改为候选对之间的真实“两两时序交替（Pairwise Switch）”；
   - 引入 `req_features` 的出图习惯签名（`client_sig`）与设备哈希（`fp`），当两把 Key 在同一非公共网络具备相同 `client_sig` 时赋予强关联权重；
   - 识别短时交织出图（如 10 分钟内交替使用）。
2. **新增离线智能审计工具（`deploy/ops/sybil_audit.py`）**：
   - 站长只需运行 `python3 deploy/ops/sybil_audit.py`，即可一键自动从生产数据库或导出的 CSV 中揪出所有一人多号、死循环脚本与异常错误。
3. **前置参数校验加固（`app/policy.py`）**：
   - 检测并拦截异常深层嵌套提示词（如超出 8 层的连续大括号/圆括号 `{{{{{{{{`），防止导致 NovelAI 上游 GPU 计算溢出报错 NaN。
